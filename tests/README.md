# Проверки ЛР1

`make test` собирает программу и cmocka-тесты с ASan/UBSan
(`-fsanitize=address,undefined`, без восстановления после ошибки).

23 сценария проверяют:

- Формат IPC, пустое/максимальное тело, multicast, частичный приём,
  круговой обход и ошибки формата/EOF.
- Возврат EAGAIN из receive()/receive_any() при пустом канале и дочитывание
  начатого кадра за один вызов, включая задержку между фрагментами.
  Следующее сообщение остаётся в канале до следующего вызова.
- Однократное событие EOF с ID отправителя, закрытие дескриптора, работа остальных каналов
  после EOF и завершение receive_any(), когда все каналы закрыты.
- Приём вилки/маркера без отправок и одна попытка обслуживания за шаг диспетчера.
- O_NONBLOCK на обоих концах сразу после создания каналов; сохранение нужных
  концов и фактическое закрытие чужих. Очистку частично созданной сети и
  безопасность повторного закрытия при переиспользовании номеров дескрипторов.
- Переполнение настоящего pipe: 256 атомарных сообщений, повтор после EAGAIN,
  порядок кадров и обслуживание другого получателя.
- EINTR, EAGAIN и обнаружение нарушения атомарности через подмену write.
  Подмена применяется только при сборке модульного тестового исполняемого
  файла, не программы и не сдаваемого архива.
- Начальное распределение вилок/маркеров, отсутствие повторного запроса,
  удержание чистой вилки, передачу грязной, запрет передачи в КС
  и полное условие входа.
- Управляемую модель четырёх философов с восемью порядками доставки.
  После каждого шага проверяются уникальность вилки и маркера с учётом
  сообщений в пути, отсутствие двух EATING и обслуживание всех запросов.
- Запросы во время стартового барьера, ранний DONE, обслуживание после
  своей работы (в том числе после отправки DONE), EOF после DONE и закрытие
  канала конкретного ребёнка до его DONE.
- Гонку завершения: старый запрос перед ещё не обработанным DONE,
  уже закрытый pipe ответа. Отдельно — закрытие без DONE и обязательную
  доставку сообщений жизненного цикла.
- Оба режима для 0, 1, 2, 5, 9, 10 и 15 детей, ошибки CLI, оба порядка
  параметров, ровно 5 × ID итераций с единицы, события, топологию,
  пустой stderr, код 0 и таймауты.
- Непересечение интервалов входа/выхода из замедленной print() в
  настоящих дочерних процессах при --mutexl. Для этого тестовый runtime
  пишет отметки в файл с O_APPEND и задерживает print на 1 мс.
  Без флага перемешивание строк не требуется.
- Чистоту плоского архива pa6, побайтовое совпадение исходников и
  оригинальной libruntime.so. Распакованные исходники на macOS собираются
  с внешней тестовой print(); она не добавляется в архив.

Тесты находятся в `tests/test_*.c`. Общие функции запуска команд, модель
философов, проверка вывода и тестовые подмены — в `tests/util`.
Все проверки реализованы на C/cmocka, без Python.

Зависимости: clang, make, cmocka и pkg-config. Для `make lint` нужны
clang-tidy; путь можно передать через CLANG_TIDY.
TIDY_FLAGS указывает анализатору встроенные заголовки clang
(-resource-dir), а на macOS также системный SDK (-isysroot).
Эти флаги не меняют сборку самой программы.

Конфигурация включает clang-analyzer, bugprone, выбранные проверки CERT C
и запрет goto. Комментарии к заголовкам поддерживаются вручную.

```sh
make test
make lint CLANG_TIDY=/Applications/CLion.app/Contents/bin/clang/mac/clang-tidy
```

Отдельная проверка настоящей Linux-библиотеки требует Linux x86-64:

```sh
make test-linux
```

Тот же C/cmocka runner с параметром `--linux` создаёт и распаковывает
архив во временный каталог, компилирует сдаваемые исходники с -L. -lruntime
и запускает оба режима для 0, 1, 2, 5, 10, 15 детей. В эту программу
тестовая print() не включается. Проверка добавлена в Linux CI и пройдена
в контейнере Ubuntu 24.04 (`linux/amd64`) на macOS-хосте.

Оригинальная libruntime.so пишет в stderr по одному символу с задержкой.
Поэтому в этой проверке stdout содержит события, а stderr — полезную
работу. С --mutexl проверяются целые строки и порядок итераций.
Без флага допускается перемешивание символов: проверяются их ожидаемый
состав и количество. Это не доказывает порядок отдельных вызовов
в режиме без взаимного исключения. Парсер проверяется отдельным
сценарием на целых, перемешанных и испорченных данных.
Для обычной тестовой сборки требование пустого stderr сохраняется.

Таймаут одного запуска с оригинальной библиотекой — 180 секунд:
600 операций при 15 детях с --mutexl заняли 68 секунд под эмуляцией.
Перед каждым запуском тест выводит его параметры.

При проверке `linux/amd64` через эмуляцию на Apple Silicon ASan не смог
инициализироваться даже в пустой C-программе. Для этой среды тесты
запускаются с UBSan в отдельном каталоге:

```sh
make test test-linux BUILD_DIR=build/linux-ubsan \
    SANITIZER_FLAGS="-fsanitize=undefined -fno-sanitize-recover=all -g"
```

Обычный `make test` с ASan/UBSan проверен локально на macOS.

`APP_NAME` задаёт имя программы и архива во всех тестах.
`BUILD_DIR` задаёт корень артефактов. Например:

```sh
make test APP_NAME=lab1 BUILD_DIR=build/lab1
```

Транспорт отправляет каждый кадр одним неблокирующим write().
Вызывающий код передаёт корректные указатели, ID и кадры размером не больше
PIPE_BUF. В Linux предел равен 4096 байтам и покрывает MAX_MESSAGE_LEN;
на других системах он может быть меньше. Сообщения лабораторной короче
минимального предела POSIX в 512 байт; тест максимального тела учитывает
предел платформы. При приёме проверяются подпись заголовка и размер тела.

При EAGAIN ничего не записано, вызывающий код повторяет отправку,
продолжая обслуживать входящие сообщения. Вилки и маркеры остаются
у отправителя до успешной записи. STARTED/DONE повторяются адресно,
чтобы уже обслуженные получатели не получили дубликаты.
Очередей и буферов незавершённой отправки нет. Короткая запись считается
нарушением гарантии атомарности и завершает операцию с EIO.

Диспетчер использует receive_any(): 0 означает сообщение, -1 — отсутствие
данных, EOF или ошибку с причиной в errno. ReceiveContext хранит ID отправителя
последнего результата и позицию кругового обхода каналов.
Пустой канал не вызывает ожидания: receive()/receive_any() возвращают -1/EAGAIN.
После первого прочитанного байта функция дочитывает заголовок и тело прямо
в Message вызывающего кода и возвращает 0. Промежуточных буферов нет.
При EAGAIN внутри начатого кадра выполняется sched_yield() и повтор чтения;
до конца кадра другие каналы не обслуживаются. Штатный отправитель записывает
кадр атомарно, но искусственно незавершённый кадр с открытым писателем может
удерживать приём. Тестовый ребёнок дописывает такие кадры с задержкой.
При новом EOF receive_any() возвращает -1/EPIPE с ID закрывшегося отправителя;
следующий вызов проверяет остальные каналы. Если все входы закрыты, EPIPE
возвращается с sender = -1. При EAGAIN sender также сбрасывается в -1,
чтобы диспетчер не использовал прежнего отправителя. Для receive() EPIPE означает
закрытие выбранного канала. Ожидание новых сообщений выполняется в протоколе.
EOF посреди кадра остаётся ошибкой. После ошибки обмен прекращается;
повторное чтение ошибочного канала не поддерживается.
При чистом EOF дескриптор закрывается и заменяется на -1; отдельного
флага закрытия нет. O_NONBLOCK устанавливается при создании каналов,
до fork(). Дескрипторы хранятся в одной таблице ProcessIpc.descriptors
с индексами [отправитель][получатель][конец]. channels_keep_local() закрывает
чужие концы в этой же таблице; channels_close() очищает её как до, так и после fork().
philosophers_receive() только обновляет состояние, а protocol_step()
вызывает philosophers_service() один раз после обработки события.
Обработка сообщений, ожидание барьеров и сценарии родителя и ребёнка
собраны в модуле protocol; отдельного модуля dispatcher нет.

Барьеры хранят массивы STARTED/DONE по ID отправителя и завершаются только
после получения события от каждого другого ребёнка. Повтор сообщения просто
снова устанавливает флаг отправителя. Порядок STARTED перед DONE обеспечивается
кодом отправителя и FIFO-каналом, повторно он не проверяется.
Философы сохраняют полный граф конфликтов и после DONE соседа.
После своей работы процесс остаётся THINKING и обслуживает запросы вилок.

Все функции получают корректно инициализированный Process; повторной
проверки контекста в IPC нет. Проверки адресата, формата сообщения, размера
атомарной записи и ошибок ОС сохранены. После обхода пустых каналов receive_any()
вызывает sched_yield() перед возвратом EAGAIN. Фиксированной задержки нет;
это активный опрос, и процесс может сразу получить CPU обратно.
